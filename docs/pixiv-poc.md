# Pixiv 연동 PoC 경계

갱신일: 2026-10-10

사용자 요청에 따라 실행 경로를 refresh token/OAuth에서 `PHPSESSID` 쿠키와 웹 API로 변경했다. 2026-10-10 실제 계정 연결·대표 수집/변환을 확인했다. 전체 계정 최초 수집은 진행 중이며 실계정 PoC 전체 완료를 의미하지 않는다. 아래 소스 조사와 합성 계약 테스트, 실제 실행에서 확인한 범위를 구별한다.

## 웹 API 계약과 근거

- 로그인 사용자 ID는 홈페이지의 `global-data.userData.id` 또는 `__NEXT_DATA__`의 직렬화된 상태 `userData.self.id`에서 읽는다. 쿠키 접두어로 ID를 추정하거나 공개 프로필 조회를 인증 성공으로 사용하지 않는다. [PixivNow 사용자 조회 구현](https://github.com/FreeNowOrg/PixivNow/blob/master/server/routes/api/user.ts).
- 북마크는 `/ajax/user/{id}/illusts/bookmarks`의 `rest=show/hide`, `offset`, `limit`, 빈 `tag`를 사용한다. `works`, `total`, 북마크 ID별 `bookmarkTags`를 구분한다. [웹 API 설명](https://github.com/daydreamer-json/pixiv-ajax-api-docs), [북마크 응답 예시](https://github.com/daydreamer-json/pixiv-ajax-api-docs/blob/main/json/example_response/ajax/user/43192924/illusts/bookmarks_tag_offset_0_limit_3_rest_show.json).
- 작품 상세 `/ajax/illust/{id}`와 `/pages`에서 작가·태그·모든 페이지의 `urls.original`을 읽는다. 우고이라는 `/ugoira_meta`의 `originalSrc`와 프레임별 `delay`를 사용한다. 원본 ZIP 주소를 문자열 치환으로 추측하지 않는다. [PixivNow 웹 API 명세](https://github.com/FreeNowOrg/PixivNow/blob/master/docs/pixiv-web-api.md).

위 자료는 각 오픈소스 프로젝트가 관찰한 웹 계약이다. Pixiv의 안정적인 공식 공개 API 보장으로 취급하지 않는다. 응답 형식이 바뀌면 오류를 표시하며 실제 계정 호환성은 추가 검증해야 한다.

## 구현 및 자동 검증

`web.py`가 읽기 전용 웹 계약을 구현하고 `bridge.py`/`live.py`가 자식 프로세스 수명을 관리한다. 자식 프로세스 명령은 목록 한 페이지(`listing`), 작품 상세 하나(`artwork`), 완료 직전 목록 앞부분 재확인(`verify`)으로 나뉜다. 목록 행의 제목·작가·페이지 수·`updateDate`·태그 이름·`profileImageUrl`은 변경 감지와 아바타에만 쓰는 힌트다. 형식이 다르면 해당 값만 비우고 작품 상세로 확인한다. 요청 사이에는 설정 가능한 최소 간격(기본 1초)을 둔다. 쿠키는 `www.pixiv.net`에만 전송하며 별도 미디어 클라이언트에는 넣지 않는다. 외부/로그인 redirect를 따르지 않고, 동일 호스트 홈페이지 언어 경로만 최대 두 번 허용한다. 응답 크기·시간을 제한하고 429에는 기존 DB cooldown과 `Retry-After`를 적용한다. 명령행·원격 오류 문자열·캐시·로그·sidecar·API 응답에 쿠키를 넣지 않는다.

`tests/test_pixiv_web.py`는 legacy/Next.js 인증 상태, 익명 세션 거부, 공개/비공개, 목록 행 힌트, 다중 페이지, 태그 원문/언어별 번역, 명시적 빈 태그와 필드 누락, 접근 불가 작품, 우고이라 ZIP/타이밍, redirect·401·403·429·5xx, 재개 offset 경계와 변경된 목록, 요청 간격을 검증한다. 홈페이지 인증 없는 공개 북마크 응답을 수집 성공으로 취급하지 않는다.

페이지마다 한 항목을 겹쳐 직전 북마크 ID와 전체 건수를 확인하고, 완료 직전 첫 항목·건수를 재검사한다. 변화가 감지되면 `collection_changed`로 끝내고 재시도 시 처음부터 확인한다. 원격의 동시 편집을 완전하게 격리하는 스냅샷은 없으므로 실계정 재북마크 시나리오 검증이 필요하다.

`tests/test_cookie_migration.py`는 v2의 암호화 자격 증명 보존·유형 분리, 검증 상태 무효화, OAuth 커서 초기화와 멱등 마이그레이션을 확인한다. 이전 refresh token은 쿠키로 보내지 않으며 새 쿠키 등록 시에만 교체한다.

기존 `gallery-dl` 1.32.13 정규화 코드는 오프라인 fixture 검증용으로 남긴다. worker는 gallery-dl의 OAuth 함수나 App API를 호출하지 않는다. 새 웹 어댑터는 참조 프로젝트의 코드를 복사하지 않고 애플리케이션 계약에 맞춰 작성했다.

## 실제 계정 확인과 남은 항목

연결 검증 작업은 성공해 `connected`로 기록됐다. 공개 목록 15개를 완료했으며 비공개 목록의 당시 전체 수는 4,842개였다. 2026-10-10 16:33 KST 확인 시 공개/비공개 작품 110개, 원본 다운로드 항목 808개가 ready이고 실패/메타데이터 오류는 0개였다. 비공개 커서는 95이며 최초 수집은 계속 진행 중이다. 공개 첫 묶음의 60개 완료 다운로드에서 일시정지한 뒤 동일 작업을 재개해 완료 파일을 유지한 채 후속 다운로드가 진행되는 것을 확인했다. web 재시작은 실제 쿠키·로그인 세션·worker 수집을 유지했다.

실제 우고이라 4개는 ZIP 검사와 프레임 목록/타이밍 대응, 단일 H.264·yuv420p MP4를 확인했다. 프레임 수/원본 타이밍 합계 → MP4 길이는 각각 229/22.900초 → 22.901초, 149/12.367초 → 12.368초, 156/6.500초 → 6.501초, 103/5.150초 → 5.151초였다. 원본 ZIP/타이밍은 보존했고 GIF 재생 파일은 생성하지 않았다. 그 뒤 완료된 추가 변환은 이 4개에 대한 개별 검사 결과에 포함하지 않는다. 실제 보관 검사 작업은 시작 범위 522개 파일을 크기·해시 오류 없이 완료했으며 이후 수집한 파일의 검사를 완료했다는 뜻은 아니다.

같은 날 후속 버그 점검에서 다른 실제 우고이라 1개의 변환 실패를 발견했다. 원본 80프레임/5.030초의 PTS는 맞았지만 B-frame 재정렬이 있는 MP4 컨테이너 길이가 4.991초여서 검증에서 실패했다. `-bf 0` 반영 후 동일 실패 작업을 재시도해 5.031초 MP4로 성공했고 모든 프레임 시각·ZIP/타이밍 해시를 확인했다. 19:02 KST의 완료 다운로드는 10,070개이며 수집은 계속 진행 중이다. 초기 확인 때의 4개 성공을 모든 실제 자료의 변환 성공으로 일반화하지 않는다.

| 항목 | 상태 | 필요한 확인 |
| --- | --- | --- |
| PHPSESSID 연결·사용자 ID | 실제 연결 성공 | 실제 만료 응답 구분은 미검증 |
| 공개/비공개 목록·태그 | 공개 목록 완료·비공개 일부와 작품 태그 확인 | 비공개 전체 완료/대조, 비어 있지 않은 북마크 태그 사례 |
| 재북마크·일시정지·페이지 재개 | 실제 다운로드 일시정지/재개 확인 | 재북마크 중 목록 변경 감지와 전체 누락 대조 |
| 다중 페이지 원본 | 실제 다운로드와 시작 범위 크기/해시 확인 | Pixiv 최고 해상도·형식/품질 대조와 전체 계정 검사 |
| 우고이라 ZIP 품질 | 실제 ZIP/타이밍·MP4 4개 확인 | 서버 originalSrc와 개별 최고 해상도 프레임의 품질 대조 |
| 403·429·네트워크 오류 | 합성 검증만 | 실제 거부/요청 제한/만료 응답 |
| 목록 행 변경 힌트 | 미검증 | 제목·태그·이미지 교체가 `updateDate`·태그 목록에 반영되는지 |
| 요청량과 간격 | 미검증 | 일반/전체 갱신의 실제 요청 수와 429 발생 여부 |
| 프로필 이미지 | 미검증 | `profileImageUrl` 형식과 미디어 서버 응답 |

현재 표시 등급 정책으로 R18 작품이 라이브러리에서 숨겨지는 것은 수집 실패와 구별한다. 이 검증에서 사용자 표시 정책을 변경하거나 실제 민감한 미디어를 브라우저에 표시하지 않았다. 실제 영상의 브라우저 재생, worker 강제 종료/Redis 유실·복원·장시간 제한 이후의 실계정 재전달은 미검증이다. 자동 테스트 217개 및 Origin/CSRF 확인, 자격 증명 비노출과 격리 테스트 자료 정리는 [검증 기록](validation.md)을 따른다.

쿠키 저장 직후는 `unverified`, 별도 worker 검증 성공 후에만 `connected`다. 만료된 쿠키는 자동 갱신하지 않으며 설정에서 새 값을 등록한다.

## 우고이라 로컬 변환

원격 ZIP과 타이밍을 원본으로 보존한다. ZIP 실패를 대표 이미지로 대체하지 않는다. 합성 프레임으로 FFmpeg H.264 변환, FFprobe 재생 길이, 인증된 HTTP Range 응답, 브라우저 반복 재생을 검증했다. ZIP 경로 탈출·중복·심볼릭 링크·압축량·타이밍을 제한하고 검증 후 생성한 로컬 PNG만 변환한다. [FFmpeg concat](https://ffmpeg.org/ffmpeg-formats.html#concat-1), [Python ZIP 문서](https://docs.python.org/3/library/zipfile.html).
