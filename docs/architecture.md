# 현재 구현 경계

웹 요청은 FastAPI 계약을 통해 서비스로 들어간다. API 핸들러에는 SQL·파일 조작·Pixiv 요청을 넣지 않는다. DB 상태와 outbox가 작업 기준이며 Redis는 전달 수단이다. `002_collection.sql`은 수집·변환 구조를, `003_cookie_auth.sql`은 자격 증명 종류와 쿠키 전환 상태를 추가한다. 이전 OAuth 커서는 초기화하지만 작품·원본·완료 파일 작업은 유지한다.

`CookiePixivAdapter`는 별도 프로세스에서 Pixiv 웹 API를 읽는다. PHPSESSID는 stdin으로만 전달하며 명령행·stderr·캐시에 남기지 않는다. 홈페이지의 legacy `global-data` 또는 Next.js 상태에서 로그인 사용자 ID를 확인한다. 쿠키는 고정 `https://www.pixiv.net` 요청에만 사용하고 로그인 페이지나 다른 호스트로의 redirect를 따르지 않는다. 홈페이지의 동일 호스트 언어 경로 redirect만 제한적으로 허용한다. 원본 다운로드는 쿠키가 없는 별도 클라이언트로 수행한다. 실계정 PoC는 미완료다.

`CollectionRun`은 공개·비공개마다 별도 커서와 세대를 가진다. 웹 커서는 offset·전체 건수·직전/첫 북마크 ID를 보존한다. 한 항목을 겹쳐 조회해 재개 경계를 확인하고 완료 직전 첫 항목·전체 건수를 다시 비교한다. 변화가 감지되면 `collection_changed`로 중단하여 `not_seen`을 확정하지 않는다. Pixiv가 목록 스냅샷을 제공하지 않으므로 동시 편집의 모든 형태를 감지한다고 보장하지 않는다. 작품·북마크·태그·다운로드 대상과 커서를 한 트랜잭션으로 기록한다. 전체 열거가 확인되어야 해당 범위만 `not_seen`으로 바뀐다. 기존 파일과 수동 태그는 삭제하지 않는다. 원본 URL이 달라지면 새 불변 파일 리비전을 만들고 이전 파일을 유지한다. 동일 URL의 콘텐츠가 원격에서 조용히 교체되는 경우는 현재 재다운로드 없이 감지하지 못한다.

원본 저장은 검증·임시 파일 fsync·staged DB 기록·원자적 이동·ready DB 기록 순서다. 다운로드 대상에 staged asset을 연결해 이동 직후 중단되어도 재다운로드 없이 조정한다. 네트워크·해시·변환 중에는 SQLite 쓰기 트랜잭션을 잡지 않는다. 이미지 파일은 Pillow로, 우고이라는 ZIP 항목/압축량/프레임 이미지와 타이밍으로 검증한다.

우고이라는 ZIP과 타이밍 JSON을 같은 리비전으로 보존한다. `UgoiraBundle`과 변환 작업/outbox는 함께 기록한다. 변환 작업은 로컬 원본으로 첫 프레임 썸네일과 H.264 MP4를 만들고 FFprobe로 코덱·총 재생 길이를 검사한다. 파생 파일은 콘텐츠 해시 경로로 저장해 재생성 시 기존 파일을 덮어쓰지 않는다. 수집 작업은 `waiting_children`에서 변환 결과를 기다리며 실패를 합산한다. 원본 보관 상태는 변환 실패와 독립적이다.

계정 작업은 계정 lease, 변환은 작품별 lease를 사용한다. 429 cooldown은 DB에 저장해 재시도/다른 계정 작업에서도 `Retry-After`를 지킨다. 일시정지·취소는 네트워크 코루틴/자식 프로세스 종료와 파일 쓰기 종료 확인 후 반영하며, 부모 명령은 연결된 변환 작업에도 전달된다. Linux 자식 프로세스는 부모 강제 종료 시 함께 종료된다. 만료된 lease의 이전 소유자는 결과를 반영하지 못한다.

미디어 ZIP·JSON·썸네일·영상에는 이미지와 동일한 앱 인가/등급 제한을 적용한다. 영상은 인증된 Range 요청으로 제공한다. 재생은 자동 시작하지 않으며 사용자 조작, 반복 재생, 브라우저 전체 화면 기능을 사용한다.

`ArtworkQuery`가 검색 입력·열거형·태그 개수·날짜 범위를 검증한다. `services/search.py`가 목록·작가/태그 집계·이전/다음 작품에 동일한 SQL 조건과 안정적인 정렬을 적용한다. 숨긴 등급과 tombstone은 명시적 필터로도 노출하지 않는다. 태그 출처는 포함/제외와 자유 검색의 태그 부분에 적용하며, 제목/작가 이름의 검색에는 영향을 주지 않는다. 원문 태그 정확 일치와 자유 검색의 NFKC/casefold 부분 일치를 구분한다. 작가 별칭·작품 메모는 기존 로컬 컬럼만 갱신하므로 추가 DB 마이그레이션이 없다.

프런트엔드는 반복 `tag`/`exclude_tag` 쿼리와 필터·정렬·페이지·카드 크기를 URL에 보관한다. 목록별 스크롤/카드 ID는 탭 세션에 저장하고 상세 복귀와 브라우저 뒤로 가기에서 복원한다. 전체 화면 뷰어는 100~400% 확대, 포인터 이동, 맞춤 상태에서 수평 스와이프, 좌우/+/−/0/Escape 키를 지원한다. 우고이라 영상 재생은 기존 네이티브 컨트롤을 사용한다.

## 첫 설정 안내 (2026-10-04, 기능 검증 대기)

관리자 생성 성공 후 인증된 `/setup`을 지연 로딩한다. 기존 관리자의 일반 로그인은 요청 경로를 유지하고 설정에서 안내에 다시 진입한다. `PixivCollectionCards`를 설정/안내가 공유해 암호 입력·쿠키 저장/삭제 뒤 이전 작업 결과 초기화·연결 검증·범위/방식 선택·수집 작업 링크를 같은 API와 쿼리 캐시로 처리한다. 안내는 `StorageCard`와 `DownloadPolicyCard`도 공유하며 지원 유형과 나중에 연결하는 흐름을 제공한다.

다운로드 정책을 성공적으로 읽고 미저장 초안/저장이 없는 동안에만 안내의 수집을 허용한다. 입력 변경과 저장 요청 시 즉시 비활성화하고 저장 성공 후 서버 응답을 캐시에 반영해 다시 허용한다. 계정 조회 오류/미연결 상태도 수집을 막는다. 화면 진입이 연결 검증이나 수집을 요청하지 않으며 PHPSESSID를 쿼리 캐시나 응답에 넣지 않는다. 기존 세션·저장소·설정·계정·작업 API를 사용해 계약/DB 변경은 없다. TypeScript/build 확인과 실제 관리자 생성·브라우저 검증을 구별한다.

## 작품 선택과 로컬 태그 편집 (2026-10-04, 기능 검증 대기)

`Library`는 표시 작품 ID와 선택의 교집합만 편집 대상으로 사용하고 현재 페이지 선택/해제와 범위 안내를 제공한다. 경로·서버 검색/고정 범위 변경 시 선택을 초기화한다. 요청 시점의 ID 목록·태그 이름·작업을 `useArtworkTagEdit` 변수로 전달하고 처리 중 입력/선택을 비활성화한다. 성공/오류는 편집 영역 밖에 표시해 목록이 비어도 결과를 알 수 있으며 같은 선택의 완료 후 목록 제목에 focus를 돌린다. 상세 편집도 명시적인 작품 ID를 전달한다. 태그 생성/이름 변경과 같은 갱신 함수를 사용해 작품·태그·작가 집계 및 이전/다음 캐시를 다시 읽는다.

`library.edit_tags`는 중복 ID를 제거하고 짧은 쓰기 트랜잭션에서 모든 대상의 조회 권한을 먼저 확인한다. 추가는 로컬 관계만 한 번에 중복 없이 삽입하고 제거는 이름이 있을 때 해당 로컬 관계만 한 번에 지운다. 없는 태그 제거로 사전을 만들지 않으며 원격 관계와 번역은 변경하지 않는다. 기존 `TagEdit`의 명시적 ID 최대 100개 계약과 204 응답을 유지한다. 완료 안내의 작품 수는 요청 대상 수이며 실제로 새로 생기거나 사라진 관계 수가 아니다. API/DB 변경은 없다.

## 모바일 상세 정보 (2026-10-04, 기능 검증 대기)

## 예약 범위와 작업 요청 (2026-10-04, 기능 검증 대기)

마지막 목록 페이지의 검증이 끝난 `collection.checkpoint`에서 범위 내 `CollectionItem`의 정보/북마크 태그 오류를 확인하고 `last_public_full_sync_at` 또는 `last_private_full_sync_at`을 같은 DB 트랜잭션으로 기록한다. 접근 불가와 제외는 따로 취급하며 원본/변환 완료를 뜻하지 않는다. `schedule.full_due`는 현재 예약 범위의 기록을 읽고 `all`은 두 기록의 최솟값을 사용한다. 범위가 미기록이면 갱신이 필요하며 기존 `last_full_sync_at`에서 범위를 추정하지 않는다. 두 범위가 확인되면 호환용 공통 키도 최솟값으로 기록한다. `ScheduleView.full_refreshes`에 각 범위의 nullable 시각을 추가하고 기존 `last_full_sync_at` 응답은 선택 범위의 기준 시각으로 제공한다. 스키마 v9를 유지한다.

`jobs.active_sync`는 활성 키 외에 실제 `scope`/`mode`를 확인하므로 이전 키 형식의 작업도 조회한다. 같은 범위의 full은 normal 요청을 충족하지만 역방향은 합치지 않는다. 새 활성 키는 범위와 방식을 포함하고 기존 idempotency key는 보존한다. full과 normal 또는 다른 범위의 요청이 함께 남아도 계정 lease로 하나씩 실행한다. 재개/재시도도 같은 조회를 사용하며 새 키와 종료 중 작업이 충돌하면 안정적인 `job_stopping` 오류를 반환한다. 예약은 같은 정책으로 합침/신규 작업을 판단한다. 기존 작업/공통 시각/백업·다중 worker·부분 실패 검증은 대기다.

## 부모 요청과 공유 변환

`jobs.action`은 부모의 허용 상태와 활성 작업 합침을 먼저 결정한다. 기존 작업을 반환하거나 오류로 거부하는 요청은 원래 부모의 하위 상태·연결·outbox를 변경하지 않는다. 받아들인 재개/재시도에서 paused 변환을 재개하고 재시도 대상이 다른 활성 변환을 반환하면 `JobDependency`를 그 작업으로 옮긴다. 기존 변환의 작업/이벤트 행은 유지한다. 취소된 변환은 명시적 부모 재시도에서 새 요청으로 만들며 tombstone이 있는 원본은 다시 변환하지 않는다. 자식이 pausing/cancelling이면 `job_stopping`으로 전체 트랜잭션을 되돌리고 실제 종료 뒤 재요청하도록 안내한다.

변환은 여러 부모가 공유할 수 있다. 다른 queued/running/waiting_children 부모가 있으면 한 부모의 pause/cancel로 중단하지 않는다. 취소 요청에서 다른 pausing/paused/waiting_auth/waiting_storage 부모가 남으면 변환을 취소하지 않고 일시정지해 재개 가능 상태를 보존한다. 중단 요청·실행 종료·lease 회수·부모 결과 조정은 같은 공유 수요 조회를 사용한다. 부모 자신의 작업 프로세스와 그 부모를 위해 중단한 변환은 종료 확인을 기다리며 다른 진행 부모에 필요한 변환은 해당 부모가 관리한다. 재개가 기존 부모에 합쳐지면 화면에 반환 작업 링크를 표시한다. API/스키마는 유지하며 기능·경합·브라우저 검증은 대기다.

## 원본별 미리보기와 로컬 재생성

`010_original_thumbnail.sql`은 `asset.thumbnail_id`의 nullable 자체 참조와 인덱스를 추가한다. 새 파생 파일을 원자적으로 ready 확정한 뒤 별도의 짧은 트랜잭션에서 원본과 연결한다. 연결 전 중단되면 파일은 보존하고 다음 생성/검사에서 같은 바이트를 재사용해 연결한다. 같은 파생 SHA-256을 여러 원본 리비전에서 재사용할 수 있으며 기존 행 생성 순서로 출처를 추정하지 않는다. 목록은 원본의 ready 미리보기를 선택하고 연결이 없으면 원본을 사용한다. 보완도 이 연결과 파일 상태를 확인한다. 우고이라는 최신 bundle의 미리보기를 선택한다. 백업 DB가 관계를 보존하고 복원된 파일이 누락/손상이면 다음 로컬 생성에서 보완한다.

`services/previews.py`는 `POST /artworks/:id/preview`에서 앱 표시 권한·tombstone·일반 이미지/첫 페이지 원본 기록을 확인하고 jobs/outbox를 영속화한다. Pixiv 인증이나 다운로드 등급 선택은 요구하지 않는다. worker는 원본 크기/SHA-256 확인, 공유 공간 예산, 파생 WebP 저장/연결을 수행하며 원본을 수정하지 않는다. preview는 삭제/변환과 같은 작품 lease를 공유하고 삭제 요청이 대기/멈춤/실행 preview를 취소해 종료 확인 뒤 원본을 지운다. 실패는 작업/문제 기록으로, ENOSPC/EDQUOT는 waiting_storage로 남긴다. 상세는 펼쳐진 동안 요청 작업을 조회하며 완료 후 작품/파일/목록을 갱신한다. 보관 검사의 보완 오류도 source asset에 `preview_failed` 등 안정적인 코드를 기록해 partial로 남기고 시작 시 asset 상한 안의 원본이 있는 작품만 보완한다. 기능·업그레이드·경합·브라우저 검증은 대기다.

## P4 지속 동기화와 보존

장시간 실행 복구(2026-10-04, 기능 검증 대기): outbox는 전달마다 새 Redis UUID를 사용하고 `run_job`에는 영속 DB 작업 ID를 전달한다. 이전 Redis job/in-progress 키가 남아도 새 전달을 받을 수 있으며 DB claim·lease가 중복 실행을 차단한다. 최대 100개 전달을 미전달/가장 오래된 전달 순으로 고른다. arq의 3600초 제한은 실행 시도 단위다. 취소/시간 제한/worker 종료 시 서비스의 디스크 작업과 자식을 먼저 기다리고, 해당 소유권이 유효하면 `continue_interrupted`가 진행 기록을 유지해 queued/outbox 미전달로 확정한다. 사용자의 pausing/cancelling은 paused/cancelled로 확인한다. 오래된 소유자는 새 실행에 영향을 주지 못한다.

보관 검사는 `Job.summary`의 버전 1 체크포인트에 시작 Asset rowid 상한, 마지막 파일 rowid, 검사 단계, 마지막 미리보기 작품 ID를 저장한다. 결과/문제/처리 수와 커서는 같은 짧은 트랜잭션에서 확정하고 해시는 밖에서 계산한다. 미리보기 원본도 시작 행 범위 안에서 선택하며 같은 파일의 문제를 중복 합산하지 않는다. 종료된 failed/partial 검사의 재시도는 새 검사이고 paused/waiting_storage는 계속 진행한다. 오래된/잘못된 체크포인트는 재검사 이벤트와 함께 초기화한다. 백업 복원은 미완료 검사의 체크포인트/문제/처리 수를 초기화하며 완료 이력은 보존한다. 스키마/API 변경은 없다.

어댑터 계약은 목록 페이지(`listing`), 작품 상세(`artwork`), 완료 직전 목록 앞부분 재확인(`verify`)으로 나뉜다. 자식 프로세스의 명령 하나는 목록 한 페이지 또는 작품 하나만 처리하고, 웹 요청 사이에 설정된 최소 간격을 둔다. `services/collection.py`가 목록 행마다 상세 요청 여부를 정한다. 판단 기준은 작품 존재, 보관 완료 여부, 원격 접근 상태, 마지막 상세 확인 시각, 마지막 상세 확인 때 기록한 목록 행 지문이다. 상세는 트랜잭션 밖에서 받고, 작품·북마크·태그·다운로드 대상·커서를 페이지 단위 트랜잭션으로 기록한다. 마지막 페이지는 상세를 모두 받은 뒤 목록 앞부분과 총건수를 다시 확인하고 나서 `not_seen`을 확정한다.

원본 URL·타이밍과 준비된 로컬 파일이 그대로인 페이지는 다운로드 대상으로 다시 등록하지 않는다. 정상 기록의 재사용은 파일 크기로 확인하고, staged·손상·누락·읽기 실패 기록의 재사용은 전체 해시를 확인한다. 전체 해시 검사 없이 손상 기록을 정상으로 되돌리지 않는다. 일반 이미지의 첫 페이지는 원본 저장 직후 WebP 미리보기를 파생한다. 실패해도 원본 저장 결과는 바뀌지 않는다. 목록의 프로필 이미지 주소는 작가에 기록하고, 쿠키가 없는 미디어 클라이언트로 받아 `data/avatars/{artist_id}/{sha256}`에 저장한다.

`CollectionItem.outcome`은 신규·변경·재확인·최신 유지·제외·접근 불가·정보 실패를 구분한다. 접근 불가는 실패 수에서 뺀다. 끝난 수집은 집계를 `job.summary`에 남기고 오류가 없는 북마크별 행을 지워 예약 실행이 DB를 계속 키우지 않게 한다. `services/schedule.py`는 설정과 다음 실행 시각을 `setting` 테이블에 두고 worker의 5초 주기에서만 판단한다. 같은 실행 시각의 작업은 idempotency key로 한 번만 만든다.

`services/retention.py`의 로컬 삭제는 tombstone(`deleting`)과 삭제 작업·outbox를 한 트랜잭션으로 기록하고 대기 중인 다운로드와 변환을 멈춘다. 삭제 작업은 같은 작품의 변환 lease를 공유해 실행 중인 변환이 끝난 뒤 파일을 지운다. 파일마다 asset을 `deleted`로 바꾸고, 빈 디렉터리를 정리하고, 우고이라 bundle을 지운 뒤 tombstone을 `deleted`로 확정한다. `store_blob`은 이동 전후에 tombstone을 다시 확인해 늦게 끝난 다운로드가 파일을 되살리지 않게 한다. 제외 해제는 tombstone 삭제와 선택적 `restore` 작업을 한 트랜잭션으로 묶는다.

`services/export.py`는 작품 ZIP을 임시 파일 없이 스트리밍하고 전체 메타데이터를 작품 200개 단위로 JSON 스트리밍한다. `services/backup.py`는 SQLite 온라인 백업 API로 스냅샷을 만들고 참조 파일만 미러·복원한다. `core/redaction.py`는 web·worker 로그 핸들러에 마스킹 필터를 붙인다. 시스템 상태는 역할별 보관 용량, DB 크기, 작업 대기열, 예약 여유 공간을 반환한다.

백업 미러는 소스와 기존 미러의 크기/SHA-256을 검사한다. 현재 아바타는 콘텐츠 해시 파일명을 비교 기준으로 사용하며, 과거 해시 없는 경로는 소스의 실제 해시로 복사하되 백업과 `--hash` 검사에서 `unverifiable`로 구별한다. `copy_file`은 일반 파일을 열어 크기 상한·해시·읽기 전후 상태를 확인하고 0600 임시 복사본을 fsync/재검사한 뒤 원자적 이동과 디렉터리 동기화를 수행한다. 복원도 이 경로를 공유하며 원본의 DB 해시/현재 아바타의 파일명 해시는 복사 중 항상 비교한다. `--verify-hash`는 미러를 먼저 해시 검사하고 기준 없는 과거 아바타를 누락으로 처리한다. 옵션이 없으면 과거 아바타도 복사하되 `unverified_avatars`로 구별한다. 잘못된 참조는 조용히 제외하지 않고 실패시키고 참조 조회는 iterator로 순회한다.

백업 출력의 `.backup.lock`으로 같은 출력의 실행을 직렬화한다. 0700 `.pixchive-backup-*`에서 0600 DB와 manifest를 준비하고 파일/디렉터리 동기화 뒤 `pixchive-backup-*`으로 이름을 바꾼다. 원본이 없어도 기존 미러가 DB 해시와 맞으면 재사용할 수 있으며 원본 문제 수와 실제 미보관 수를 구별한다. manifest 포맷은 v1을 유지하고 `media.complete`/`unavailable`/`unverifiable`/`mismatched_in_source`/검증 방식 필드를 추가한다. 미보관 또는 해시 기준 없는 파일이 있으면 CLI 종료 코드 1과 진단용 스냅샷을 남기며 `last_backup_at`을 갱신하지 않는다. 검사는 missing/mismatched/unverifiable 전체 수와 최대 20개 예시를 CLI에 표시한다. 이 후속 변경의 기능·강제 종료 검증은 대기 상태다.

`core/data_state.py`는 `.data-access.lock`의 프로세스 수명 공유/복원 독점 잠금과 중단된 복원의 시작 차단을 담당한다. web lifespan·worker 시작부터 종료까지·로컬 쓰기 CLI는 공유 잠금을 유지하며 복원은 독점 잠금을 즉시 시도해 이미 사용 중이면 실패한다. 잠금은 SQLite 트랜잭션이 아니며 FD는 변환 자식에 전달하지 않는다. 정상 시작과 일반 CLI의 DB 초기화는 `.restore-incomplete` 또는 `pixchive.db.restoring`/보조 파일이 남아 있으면 거부한다. 내용이 불명확한 표식도 삭제하거나 완료로 추정하지 않는다.

복원은 독점 잠금을 잡고 대상·소스를 확인한 뒤 0600 시작 표식을 fsync한다. `pixchive.db.restoring`과 미디어를 준비하고 해당 DB에서 마이그레이션·누락 파일 상태·lease/공간 예약/이전 응답 시각을 조정한다. WAL 체크포인트와 DELETE 저널 전환·DB 종료·검사/fsync 후 최종 `pixchive.db`로 원자적 이동하고 부모 디렉터리를 동기화한 뒤 표식을 지운다. 중단/실패하면 흔적을 남겨 시작을 차단한다. 같은 대상의 재개/병합은 제공하지 않으며 새 빈 대상으로 다시 복원한다. worker는 시작 시 파일 조정과 종료 시 모든 유지 작업의 디스크 처리를 기다리고 DB를 닫은 뒤 잠금을 해제한다. 스키마/API 변경은 없으며 실제 중단·경합 검증은 일괄 검증 대기다.

일반 이미지의 미리보기는 첫 페이지만 만든다. 대용량 성능, Docker 볼륨 복원 훈련, 실제 Pixiv 목록 필드의 변경 감지 정확도는 남아 있다. `seed-fixtures`와 테스트의 자료는 개발용 합성이며 제품 데이터에 자동 삽입하지 않는다. 지원 실행 환경은 현재 검증한 Linux x86_64/Docker이며 다른 환경은 확인하지 않았다.

## 라이브러리 제어 후속 구현 (2026-10-04, 기능 검증 대기)

`008_remote_history.sql`은 작품별 확인 시각/행 ID 정렬 인덱스를 추가한다. `remote_history.py`는 한 페이지와 비교용 직전 기록 한 개만 조회하고 태그 추가/제거를 작품·북마크 출처별로 계산한다. 읽기 불가 JSON·숨긴 등급의 기록은 상태만 반환하며 그 앞뒤 비교로 숨긴 문자열이 노출되지 않게 한다. 당시 정보 API는 검증한 원격 모델에서 허용된 표시 필드만 반환하며 원격 미디어 URL/저장 JSON/쿠키를 제공하지 않는다. 예전 최근 50개 배열 API도 같은 제한된 조회를 사용한다. 프런트엔드는 페이지별 이력과 필요할 때만 가져오는 당시 정보, 태그 번역을 표시한다.

작품 ZIP은 미리 존재/크기를 확인하고 실제 읽은 바이트를 해시/크기로 검증한다. 전송 중 오류가 나면 파일을 생략하지 않고 중단하며 정상 완료 경로에서만 ZIP 중앙 디렉터리 바이트를 전송한다. 연결 중단/오류에서도 파일/ZIP 핸들을 정리한다. `ScreenErrorBoundary`는 지연 로딩/렌더링 오류에 수동 복구 안내를 표시하며 내부 예외 내용을 제품 UI에 노출하지 않는다. 기능 테스트와 브라우저 재생/새로고침 검증은 아직 실행하지 않았다.

`005_library_controls.sql`은 로컬 태그 카탈로그 여부, 스캔의 등급 다운로드 제외 여부, `IntegrityIssue`를 추가한다. 기존 local 관계가 있는 태그는 카탈로그로 이관한다. `preferences.py`가 표시와 다운로드 설정을 분리하고, 다운로드 대상 생성과 실행 직전 모두 정책을 확인한다. 제외한 등급의 원본 보관 상태를 완료로 위장하지 않으며 메타데이터 처리 결과와 등급 제외 수를 따로 집계한다.

`local_tags.py`의 생성은 이름 중복 시 기존 태그를 재사용한다. 이름 변경·병합은 짧은 IMMEDIATE 트랜잭션 안에서 자동 관계와 번역 유무를 검사하고 로컬 관계만 이동한다. 빈 태그는 `/tags/catalog`에서 제공하며 작품 집계 API의 의미는 유지한다.

`repair.py`가 작품별 복구 작업을 계정 lease/outbox로 등록한다. 파일 해시는 트랜잭션 밖에서 확인하고 현재 원격 메타데이터를 다시 받은 뒤 누락·손상 파일만 다운로드한다. 우고이라 타이밍·재생 파일 손상도 변환 작업과 연결한다. 과거 원본 리비전을 현재 파일로 덮어쓰지 않는다. 보관 검사 문제는 작업별 영속 행으로 기록하고 `/jobs/:id/issues`에서 파일 역할·원인을 반환한다. 기능 테스트와 새 화면 E2E는 아직 실행하지 않았다.

`store_blob`은 기존 행의 작품/페이지/역할/리비전/해시/크기/해상도/형식과 수신 내용이 일치하는지 먼저 확인한다. 기존 파일의 내용이 손상됐으면 검증한 임시 파일로 원자적으로 교체하고 디렉터리를 fsync한 뒤 ready를 기록한다. 기록 없는 경로의 다른 내용이나 불일치 기록은 오류로 남기고 덮어쓰지 않는다. 이동 전 staged 기록이 남으므로 이동 후 DB 확정 전 종료는 재시작 조정 대상으로 남는다.

`data/.media.lock`의 `flock`으로 파일 최종 저장·검사와 상태 확정·실제 삭제를 직렬화한다. 파일마다 검사한 뒤 같은 잠금 안에서 결과를 저장하므로 동시 복구 뒤 오래된 검사 결과로 상태를 덮어쓰지 않는다. `verify_asset`는 잠금 획득 후 행/제외 여부를 다시 읽고 이전 실패에는 전체 해시를 적용한다. 잠금은 짧은 DB 트랜잭션 바깥에서 얻으며 대기 중 작업 guard를 확인한다. 해시 검사 중 최종 파일 저장은 기다릴 수 있으나 네트워크 다운로드·영상 인코딩은 잠금 밖에서 수행한다. 잠금 파일은 런타임 조정용이며 데이터/백업 대상이 아니다. 기능·동시 실행·장애 검증은 대기 상태다.

`directory.py`는 표시 가능한 작품이 있는 작가/태그만 상세로 제공한다. 명시적으로 만든 빈 로컬 태그는 예외로 조회 가능하다. `ArtistDetail`은 이전 이름·이름별 확인 시각을, `TagDetail`은 번역과 출처별 작품 수를 반환한다. 태그 번역과 작가 이전 이름은 목록에서 묶음 조회해 추가하고 사전/디렉터리 검색에 사용한다. `ArtworkQuery.tag_id`는 이름 대신 관계 ID로 범위를 고정하고 다른 필터와 AND로 결합한다.

프런트엔드 작가/태그 상세는 공통 `Library`를 재사용한다. 경로의 작가/태그는 고정 범위로 API 요청에 다시 적용하며 추가 필터의 초기화로 해제되지 않는다. 작품 상세의 이전/다음과 복귀는 `/library`, `/artists/:id`, `/tags/:id`의 각 URL·페이지·스크롤/focus를 보존한다. 태그 병합으로 ID가 바뀌면 대상 태그 상세로 이동한다. 새 상세/번역/목록 복귀의 기능 테스트와 브라우저 E2E는 일괄 검증 대기 상태다.

`JobQuery`는 종류·상태·실행 방법과 페이지 크기를 검증한다. `/jobs/history`와 부모/하위 작업 조회는 DB에서 집계·페이지화하며 최신 생성 시각/ID로 정렬한다. 작업 상세는 다운로드 항목 상태별 집계만 반환하고 원격 URL·내부 idempotency key·소유자 값은 노출하지 않는다. 문제/이벤트도 별도 페이지 API로 전체 기록을 탐색한다. 예전 최근 100개 배열 API는 유지한다. 스키마 v6는 이력 조회용 인덱스만 추가한다.

변환 claim은 IMMEDIATE 트랜잭션에서 모든 worker의 유효한 변환 lease를 세고 저장된 동시 실행 수(기본 1, 최대 2)를 적용한다. pausing/cancelling도 아직 종료하지 않은 실행으로 센다. 제한 감소는 이미 실행 중인 작업을 중단하지 않는다. worker 슬롯 4개는 계정 1개·보관 검사 1개·변환 2개를 수용하며 Pixiv 요청은 기존 계정 lease로 직렬화한다.

보관 검사는 시작 시점의 asset rowid 상한을 잡고 200행씩 순회하여 추가 수집과 함께 돌아도 끝나며 ID 전체 목록을 만들지 않는다. 검사 중 삭제/제외로 대상이 바뀔 수 있으므로 처리 총수는 원본 검사 종료 시 확정한다. 해시 계산은 트랜잭션 밖에서 수행한다. 이번 작업/동시성/검사 변경의 기능·브라우저·부하 검증은 일괄 검증 대기다.

## 임시 작업 공간과 worker 유지 작업

`core/files.py`는 프로세스 간 파일 잠금과 디렉터리 fsync만 제공한다. `storage.py`와 `tempfiles.py`가 같은 `.media.lock`을 사용해 파일 저장/검사와 임시 폴더 생성/회수의 경계를 조정한다. 임시 폴더 파일 삭제는 잠금 밖에서 수행한다. 파일 해시·영상 변환 중 SQLite 쓰기 트랜잭션을 유지하지 않는다.

`tempfiles.workspace`는 `data/tmp/.creating-{purpose}-{nonce}`를 0700으로 만들고 0600의 소유 잠금/format 1 표식을 기록한 뒤 `work-{purpose}-{nonce}`로 공개한다. 원본/파생 저장은 `blob`, 아바타는 `avatar`, 프레임/재생 변환은 `ugoira`다. 관리 표식과 폴더를 fsync한 뒤 이름을 공개한다. 정상/예외 종료는 본문 I/O 종료 후 `.cleaning-...`으로 바꾸고 제거한다. 이동을 끝낸 원본 파일의 staged/ready 복구는 기존 저장 서비스가 수행한다.

회수는 사용 폴더의 비차단 잠금과 format/목적/nonce가 일치하는 표식을 확인한 후 정리 단계로 바꾼다. 잠금을 얻지 못한 사용 폴더와 알 수 없는 과거 형식/표식은 유지한다. 생성 중 폴더는 생성자가 전역 경계를 잡고 있는 동안 회수할 수 없으며, 정리 중 폴더는 본문에서 더 쓰지 않는 예약된 이름이다. 심볼릭 링크·비정규 관리 파일·1 KiB를 넘는 표식을 받아들이지 않는다. 폴더 ID·목적만 기록하고 쿠키·URL·파일 원문을 표식/로그에 넣지 않는다.

활성 잠금 FD는 작업별 ContextVar로 관리하고 FFmpeg/ffprobe의 `pass_fds`에 전달한다. `child_process`는 기존 부모 종료 감시를 설정한 뒤 exec하므로 자식이 실제 종료할 때까지 소유 잠금이 유지된다. `disk_operation`과 subprocess 종료 대기가 끝난 뒤 폴더를 정리하고 공간 예산을 반환한다.

기존 arq cron은 수집/변환과 같은 작업 슬롯을 사용했다. `worker.py`는 outbox 전달·예약 판단·heartbeat를 별도 5초 코루틴으로 수행하고 한 전달 시도는 15초까지 기다린 뒤 DB/outbox에서 재시도한다. 임시 폴더 회수는 별도 코루틴에서 worker 시작 후/60초마다 최대 50개씩 디스크 스레드에서 실행한다. 실패/불명 항목 수만 로그에 남기며 파일 이름이나 원격 오류 문자열을 노출하지 않는다. 종료 시 두 코루틴을 취소하고 진행 중인 디스크 정리를 기다린다. 업그레이드 전에 Redis에 쌓인 예전 dispatcher 호출은 단회 호환 함수로 수용한다. 기능·강제 종료·포화 상태 검증은 대기다.

## 작업별 공간 예산

`009_storage_budget.sql`은 `job.storage_budget`과 `storage_reservation(job_id, owner, bytes)`를 추가한다. `storage_budget.hold`가 짧은 IMMEDIATE 트랜잭션에서 현재 작업 소유권/유효 lease를 확인하고 이전 소유자의 예약을 회수한 뒤 실제 파일시스템 여유 공간과 다른 작업의 예산을 조회한다. 여유 공간 조회는 예약 잠금을 얻은 뒤 수행하여 앞선 작업의 쓰기 완료/예약 해제를 놓치지 않는다. 네트워크·이미지 처리·프레임 생성·인코딩은 이 트랜잭션 밖에서 실행한다. 같은 작업의 중첩 예약은 더했다가 이전 값으로 되돌리며 종료 정리는 owner/예산을 비교해 새 실행의 예약을 지우지 않는다.

원본 다운로드/재사용 ZIP 조정은 최대 원본 100 MiB와 여유 8 MiB, 아바타는 5 MiB, 미리보기는 8 MiB를 잡는다. 우고이라는 검증된 타이밍의 프레임 수와 기록한 원본 해상도를 사용해 `전체 픽셀 × 5 + 프레임당 64 KiB + MP4 상한 200 MiB × 2 + 8 MiB`를 잡는다. 두 MP4 예산은 인코딩 결과와 원자적 저장 임시 복사본을 위한 것이다. PNG 압축 결과를 가정하지 않는 보수적 추정치이며 이미 생성한 임시 파일 공간도 예약에 남아 다른 작업의 시작을 더 보수적으로 제한할 수 있다.

공간 부족 시 마지막 확인의 숫자·시각을 저장한 트랜잭션을 확정하고 ENOSPC를 반환해 기존 waiting_storage 경로를 사용한다. 실제 디스크 용량 제한은 예상 공간과 별개이며 FFmpeg ENOSPC/EDQUOT 메시지는 고정된 C locale로 구분한다. 파일/임시 디렉터리 정리 뒤 예약을 해제하고, 작업 종료·lease 회수에서도 남은 예약을 정리한다. 새 설치 복원은 예약과 과거 볼륨의 공간 확인 값을 초기화한다.

API는 소유자 값 없이 마지막 공간 확인 숫자만 반환하고 설정의 전체 예약은 유효한 실행만 집계한다. 화면은 공간 대기에서 필요 용량·당시 남은 용량·확인 시각과 다른 진행 작업의 예산을 표시한다. 실제 보관 사용량과 추정 예산을 구분한다. 이 경로의 기능·동시 worker·강제 종료·복원 검증은 아직 실행하지 않았다.

## 디렉터리 조회와 병합 안내

작가·태그 화면은 `/artists/pages`, `/tags/catalog/pages`를 사용한다. DB에서 표시 가능 작품의 작가/출처별 태그를 집계한 뒤 검색·정렬·페이지를 적용하고 해당 페이지의 이름 이력/번역만 조회한다. 사전 검색은 정규화한 문자열의 `instr`로 `%`/`_`를 문자 그대로 처리한다. 페이지 총수는 작가 수/출처별 태그 행 수이며 작품 수와 구별한다. 의도적으로 생성한 미사용 로컬 태그만 0건 카드에 포함하며 숨김/제외 관계를 빈 태그로 해석하지 않는다. 이전 배열 API는 유지하고 화면의 전체 카탈로그 요청은 제거했다. 스키마 변경은 없다.

`rename-preview`는 이름을 로컬 태그 규칙으로 정규화하고 편집 가능 여부/정확히 같은 이름의 대상을 조회한다. 미리보기는 대상 정보를 잠그지 않으며 실제 이름 변경은 기존 IMMEDIATE 트랜잭션에서 보호 조건/대상을 다시 확인한다. 화면은 확인 중/실패 상태를 표시하고 확인 완료 전 저장을 허용하지 않는다. 입력 검색/미리보기는 250ms 지연과 요청 취소를 적용한다. 작가/태그 목록의 조건·페이지와 위치/focus 복귀 정보는 상세→작품→상세까지 유지한다. 기능/E2E/10만 작품 성능은 아직 검증하지 않았다.

## 수집 원문과 보관 파일 기록

`007_remote_metadata.sql`은 `Artist.account`, `Artwork.rating_evidence`, `Asset.provenance`, `DownloadTask.provenance`와 파일 종류 조회 인덱스를 추가한다. 기존 컬럼과 파일을 유지하고 새 원문/경로는 null로 둔다. 정규화 값이나 파일명으로 원문/수집 경로를 역산하지 않는다.

`RatingEvidence`는 출처·필드 이름·원문 스칼라 값을 보관한다. 필드 미제공은 evidence 없음, 명시적 null은 value=null로 구별한다. 실제 정수 0/1/2만 safe/r18/r18g로 정규화하고 bool/float/string/미지원 값은 unknown이다. 원문이 있는 어댑터 객체는 같은 값에서 정규화 등급을 도출한다. 계정명은 제공된 경우에만 갱신하며 누락은 기존 관측을 지우지 않는다. 두 정보는 원격 스냅샷에도 들어가고 작가 계정명은 공통 검색 조건과 디렉터리 검색에 포함한다. 새 미제공 필드는 스냅샷 직렬화에서 제외해 기존 관측마다 무의미한 새 리비전을 만들지 않는다.

원본 경로 종류는 어댑터의 `RemotePage.source`와 `ugoira_source`에서 다운로드 항목으로 전달하고 파일 저장 트랜잭션에 기록한다. 파생 파일은 로컬 썸네일/영상, 제공된 프레임 타이밍은 별도 종류다. 기존 출처 없는 파일은 실제 저장 과정에서 새 바이트의 확인이 이루어진 경우만 기록을 채운다. 출처는 실제 최고 품질의 증명이 아니며 실계정 확인은 P0에 남아 있다.

`inventory.py`와 `/artworks/:id/files`는 기존 등급/tombstone 접근 제한을 적용한 뒤 파일 종류/페이지로 모든 보관 리비전의 검증 상태·크기·해상도·해시·수집 경로와 ready 파일의 인증된 미디어 URL을 반환한다. 원격 URL·쿠키·절대 경로는 반환하지 않는다. 기본 뷰어와 작품 ZIP은 현재 페이지 수 범위의 페이지별 최신 ready 원본만 선택한다. 과거 확장자가 다르거나 페이지 수가 줄어도 과거 파일 자체는 유지한다.

메타데이터 포맷 v2는 원문 등급/계정명/링크·파일 상태/수집 경로를 포함한다. 전체 JSON의 파일 목록은 이전/파생 리비전까지 ID 기반 상대 경로로 나열하고 작품 ZIP의 metadata.json은 포함한 최신 파일만 나열한다. 작품 상세는 게시·처음 수집한 시각과 수집 당시 이름을 표시하고 파일 목록에서 이전 리비전도 개별로 받는다. 상세 화면을 별도 지연 로딩 청크로 빌드한다. 이 변경의 기능/브라우저/실계정 검증은 아직 실행하지 않았다.
