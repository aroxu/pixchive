## E2E 남은 관찰 수정 (2026-10-29)

사용자가 직전 전체 E2E의 남은 관찰을 모두 고치고 검증하도록 요청했다. 변경을 수반하는 시험은 격리 Compose 프로젝트의 합성 자료로 했고, 실제 로컬 서버는 활성 작업이 없을 때 web·worker를 함께 교체한 뒤 공개 범위 일반 동기화만 실행했다.

- 수정 1(worker 버전): 로컬 worker가 web보다 오래된 이미지(`163617935e3d`, 백엔드 9파일 차이)로 실행되고 있었다. 이번 이미지로 web·worker를 함께 교체해 두 컨테이너와 작업 폴더의 app 70파일 SHA-256이 같다.
- 수정 2(현재/이전 보관본): 파일 API에 `current`를 추가했다. 쪽마다 가장 최근에 등록된 원본과 그 원본에 연결된 미리보기, 최신 우고이라 묶음의 ZIP·타이밍·미리보기·영상이 현재 보관본이고 나머지는 이전 보관본이다. 손상된 최신 파일도 현재 보관본으로 남아 복구할 파일이 보인다. 화면의 각 파일에 '현재 보관본'/'이전 보관본'을 표시한다.
- 수정 3(손상 상태): 보관했던 원본(우고이라는 ZIP/타이밍)이 손상·누락·읽기 실패로 남고 정상 파일이 없으면 작품 상태를 '다운로드 대기'(pending) 대신 '일부 파일 확인 필요'(partial)로 계산한다. 처음 받을 작품과 저장 중(staged) 파일은 그대로 '다운로드 대기'다. 동기화가 완료되지 않은 작품을 다시 확인하는 기준(`complete` 여부)은 바뀌지 않았다.
- 수정 4(백업 세션): 백업 스냅샷에서 로그인 세션·로그인 시도 기록을 지우고 지운 자리를 덮어쓴다(`secure_delete`). 복원도 이전 백업에 남은 세션을 지워 항상 로그아웃 상태로 시작한다. 관리자 계정·비밀번호와 실행 중 서버의 로그인은 유지한다.
- 수정 5(검증 작업 합침): 인증 대기 중인 계정 작업에 새 요청(새 Idempotency-Key)이 오면 그 작업을 다시 대기열에 넣는다. 같은 키 재요청은 기존 상태를 그대로 돌려준다. 연결 확인 성공 뒤 자동 재개 대상에 검증 작업을 추가해 인증 대기로 남는 검증 작업이 없게 했다.
- 수정 6(짧은 비밀번호): 첫 설정 화면이 12자 미만 비밀번호와 16자 미만 설정 키를 제출 전에 막고 해당 칸에 이유를 보여 준다(오류 동안 도움말은 숨김). 서버는 `/api/setup`의 짧은 비밀번호에 `password_too_short`와 '비밀번호는 12자 이상으로 입력해 주세요.'를 돌려준다. 로그인은 길이와 관계없이 '이름 또는 비밀번호를 확인해 주세요.'로 응답한다(OpenAPI Login.password minLength 12→1, DB 스키마 변경 없음).
- 자동 검사: 네트워크를 끊은 일회용 컨테이너에서 backend **564개**(직전 557 + 신규 7, 경고 2건은 기존과 같음)와 Ruff 검사·형식 94파일이 통과했다. 실행 코드에서 OpenAPI를 다시 만들어 저장본과 frontend 타입을 갱신했고 frontend 6개·TypeScript·production build가 통과했다. 로그인 helper는 바뀌지 않아 다시 실행하지 않았다.

- 자동 회귀는 신뢰하는 HTTPS 도메인·경로의 Set-Cookie만 허용하고, 로그인 계정 확인 후 조건부 교체하는 경로를 검증한다. 다른 계정·중간 쿠키 교체·늦은 응답·수동 등록·연결 삭제가 자동 응답으로 덮어써지지 않는다. 인증 대기 작업은 같은 ID/체크포인트로 재개하고 일시정지·취소 작업은 유지한다. 동일 쿠키의 반복 검사는 불필요한 자격 증명 재저장·계정 요청을 만들지 않는다.
- 브라우저 화면은 관리자 세션·정확한 Origin·CSRF 검사 아래 HTTP/WebSocket으로 연결한다. 미인증·출처 불일치·CSRF 누락·세션 만료/철회 및 연결 삭제를 회귀로 검증했다. 공개 상태/API·내보내기에 쿠키나 내부 제어 토큰을 넣지 않는다. 429 대기는 수집과 공유하고, 사용자가 로그인 화면을 조작하는 동안 주기적 화면 이동을 미룬다. 쿠키가 없거나 검증에서 거부된 상태의 확인이 다음 재인증 시각을 계속 늦추지 않는 회귀도 포함한다. 검증 중 Set-Cookie로 바뀐 쿠키는 브라우저 후보와 저장된 자격 증명의 세대를 함께 확인해 5초마다 중복 검증하지 않는다. 검증 제한 시간 안에 끝나지 않은 429 대기도 응답을 받은 즉시 저장하며 수동 재시도로 단축하지 않는다. helper 재시작 뒤 아직 방문하지 않은 복원 프로필은 남은 10분 확인 시각을 기다리지 않고 자동 확인하며, 화면 조작 중 이동 금지도 유지한다.

기존 테스트는 바뀐 어댑터 계약에 맞췄고, 의도한 동작 변경 세 가지를 반영했다. 원격 접근 불가 작품은 실패 수에서 빠지고 `접근 불가`로 집계된다. 한 작품의 상세 형식 오류는 그 작품만 문제로 남기고 같은 페이지의 다른 작품은 계속 기록한다. 원본 URL·로컬 파일이 그대로인 페이지는 다시 다운로드 대상으로 등록하지 않는다. 일반 이미지의 첫 페이지 미리보기가 추가되어 원본 수만 세도록 고친 단언도 있다.

개발 DB 사본에 v4 마이그레이션을 먼저 적용해 확인한 뒤 실제 개발 web·worker를 재시작했다. 스키마 `1,2,3,4`, `/health`와 `/settings` 200, 로그인 없는 `/api/schedule` 401, worker의 예약 판단 주기 실행을 확인했다. 기존 관리자·표시 설정은 유지됐고 작품·작업은 0건이다. 앱 내 브라우저의 약 940px 너비에서 새 설정 화면(수집 방식, 예약 동기화, 수집 제외 목록, 저장소, 백업 카드)을 확인했다.

아직 확인하지 않은 범위: 실제 PHPSESSID로 일반/전체 갱신, 목록 행 변경 감지와 실제 요청량, 프로필 이미지. 새 화면의 데스크톱·모바일 브라우저 E2E(상세의 삭제·내보내기·이력, 작업 화면 집계·작업 기록), Docker 이미지 재빌드와 새 볼륨 복원 훈련, 10만 작품 성능도 남아 있다.

- ZIP 경로 탈출·중복·심볼릭 링크·압축 폭탄·프레임 불일치·타이밍 한도 거부.
- ZIP과 타이밍 보존, 실제 FFmpeg 변환, H.264·길이 확인, 인증된 MP4 Range 응답 206 및 미인증 401.
- 변환 실패·디스크 부족에도 원본 유지, 오프라인 재변환, 수동 재변환 성공 후 재수집 결과 재사용.
- 부모 수집 작업이 하위 변환 완료를 기다리고, 일시정지/취소 시 하위 실행 종료 확인 후 상태 확정.
- Linux 부모 프로세스 강제 종료 시 자식 프로세스 종료, 파일 저장/DB 기록 사이 장애 복구.

## P3 탐색·검색·수동 정리 검증 (2026-09-28)

- 14개 추가 테스트: 태그 AND/OR/제외·출처·중복 집계, 작품 유형/공개/보관/원격/북마크 상태 조합, 숨긴 등급과 tombstone 차단.
- UTC 날짜 시작/종료일 경계, 타임존 오프셋이 있는 게시일 정렬, 날짜 누락 제외, 잘못된 열거형·날짜 범위·태그 한도 거부.
- 동일 정렬/필터의 이전·다음 작품과 전체 위치, 페이지 경계, 검색 밖 작품, 숨긴 작품 접근 차단.
- 로컬 메모·별칭 저장/초기화와 별칭 검색, 원격 재수집 후 유지, 숨긴 작품 편집 차단, 길이/제어 문자 제한.
- OpenAPI JSON·생성 TypeScript 타입 갱신. DB 스키마는 v3 유지.

실제 사용자 데이터와 분리한 임시 DB에 합성 작품 36개/38페이지를 적재하고 실제 FastAPI 및 production frontend build로 확인했다. Pixiv 자격 증명과 요청은 사용하지 않았다.

- 1440×1000 데스크톱 필터 영역과 390×844 모바일 필터 시트, 수평 overflow 없음.
- 포함 태그 AND 0건 → OR 14건 → 제외 태그 추가 2건. 결과 없음과 필터 칩/URL 반영.
- 날짜 범위 역전 시 입력 안내, UTC 게시일 2일·비공개 조합 2건 및 일부 보관 상태 표시.
- 페이지당 12개/큰 카드 URL 유지, 검색 결과 12번째→13번째 작품 이동 후 목록 2페이지 복귀.
- 메모 여러 줄·작가 별칭 저장과 새로고침 후 유지, 작가 목록의 별칭 검색.
- 모바일 명시적 두 작품의 로컬 태그 일괄 추가→태그 목록 2건→출처를 유지한 탐색→일괄 제거→0건.
- 전체 화면 150% 확대, 드래그 위치 변화, 키보드 및 모바일 너비에서 포인터 스와이프 1→2페이지. 페이지가 바뀌면 확대를 초기화한다.
- Escape/닫기 후 크게 보기 focus 복귀, 상세 돌아가기와 브라우저 뒤로 가기 후 목록 중간 스크롤·카드 focus 복귀.
- 모달을 열 때 배경 스크롤 잠금, 모바일 편집 컨트롤 표시, 런타임 오류 로그 확인.

최종 `pixchive:local` Docker 이미지 빌드도 통과했다. 개발 web/worker가 실행 중이며 `/health`와 `/settings` 응답, worker heartbeat를 확인했다. 기존 관리자/표시 설정과 자격 증명 0건·작품 0건을 유지했다. 임시 검증 서버는 종료했다.

위 제스처 검증은 브라우저 포인터 조작이다. 실제 휴대폰 터치·멀티터치 핀치는 검증하지 않았다. 10만 작품 성능 측정도 미실시다.

## 실제 Compose 및 worker 검증

일반 데이터와 분리한 `pixchive-smoke` 프로젝트에서 검사했다.

1. 이미지 build와 web/worker/Redis 시작.
2. 빈 볼륨 마이그레이션과 초기 키 생성.
3. 합성 작품 6개, 원본 8개 적재 및 관리자 세션 생성.
4. HTTP 202로 보관 검사 작업 등록, 실제 Redis 전달, worker에서 8개 파일 검증 완료.
5. worker 정지 상태에서 작업 생성, 테스트 Redis `FLUSHALL`, web/worker 재시작.
6. 기존 세션·작품 유지 및 queued DB 작업의 자동 회수·완료 확인.

기본 Docker bridge가 없는 호스트 특성으로 이미지 build에는 `--network=host`를 사용했다. 런타임은 Compose 전용 bridge다. 호스트 Docker 설정이나 다른 프로젝트는 수정하지 않았다. 실계정 동기화·실제 다운로드 중 강제 종료·장시간 부하·전체 백업 복원은 이 검증에 포함되지 않는다.

P2 이미지에 FFmpeg를 포함한 뒤 별도 합성 DB와 Redis DB 1로 ARQ worker를 실행했다. DB outbox의 변환 작업 전달 → ZIP/타이밍 검증 → 썸네일·MP4 생성 → 작업 `succeeded`와 bundle `ready`를 확인했다. 원본 2개가 남아 있고 파생 파일의 해시 검증이 통과했다. 실제 개발 서비스의 Redis DB 0과 데이터는 이 테스트에서 사용하지 않았다.

개발 환경 `localhost:8000`에도 스키마 v2와 최신 UI를 반영했다. 기존 관리자·표시 설정을 유지했고, `compose.dev.yml`의 Redis와 독립 worker 연결을 확인했다. 실계정 토큰 등록이나 Pixiv 요청은 실행하지 않았다.

## 쿠키 인증 전환 검증 (2026-09-28)

- PHPSESSID 암호화 보관, 값만 허용하는 입력 검증, 응답/검증 오류의 쿠키 비노출.
- legacy HTML 및 Next.js 홈페이지의 로그인 사용자 ID 검증, 익명/만료 세션 거부.
- 웹 API 공개/비공개 범위, 원본 페이지, 태그 원문/언어별 번역, 우고이라 `originalSrc`와 타이밍.
- 로그인/다른 호스트 redirect 거부, 홈페이지 언어 경로만 허용, 미디어 요청에 쿠키 없음.
- offset 재개 시 직전 항목과 총건수 확인, 종료 전 첫 항목/총건수 변경 검사.
- sparse/빈 북마크 태그 응답과 필드 누락 구분, 목록 형식 누락을 완료로 해석하지 않음.
- v2→v3 마이그레이션에서 이전 토큰 암호문 보존·쿠키 전송 차단·기존 커서 초기화.
- 실제 개발 서버와 worker를 v3로 재시작하고 기존 앱 로그인·표시 설정 유지 확인.

쿠키 전환 시점의 121개 테스트에는 이전 OAuth 테스트를 대체한 웹 API 계약 테스트가 포함된다. 실제 PHPSESSID 등록과 Pixiv 요청은 실행하지 않았다. 상세 조사 근거와 한계는 [Pixiv PoC](pixiv-poc.md)에 있다.

## 브라우저 E2E

FastAPI가 제공하는 실제 production build, 합성 원본, 임시 관리자 세션으로 확인했다. API 응답을 프런트엔드 mock으로 대체하지 않았다.

- 첫 설정 화면 표시 및 관리자 로그인.
- 1440×1000 desktop 라이브러리, 390×844 mobile 레이아웃과 수평 overflow 없음.
- 3페이지 작품의 다음 페이지 이동.
- 로컬 태그 추가 후 새로고침에도 유지.
- 한국어 로컬 태그 부분 검색과 검색 URL 반영.
- 전체 화면 뷰어, Escape 닫기, 버튼 focus 복귀.
- 목록 돌아가기 후 카드 focus 복귀.
- mobile 필터 열기/닫기와 focus 복귀.
- mobile 로그아웃 즉시 private 화면 제거 및 로그인 화면 전환.
- 우고이라 상세의 ZIP·타이밍 링크, 포스터와 MP4 컨트롤, 실제 반복 재생 확인. 합성 원본 400ms의 MP4는 401ms이며 재생 시 `currentTime`이 진행하고 오류가 없었다.
- 1280px desktop과 390×844 mobile에서 우고이라 상세 비율 유지 및 수평 overflow 없음.
- 설정의 수집 범위 선택 → 비공개 수집 등록 → 작업 목록 범위 표시 → 일시정지 → 취소 상태 반영. 네트워크 수집을 실행하지 않는 분리된 합성 환경에서 확인했다.
- 실제 개발 화면 새로고침 후 기존 로그인 유지, 새 수집 UI·우고이라 지원 설명·worker 연결 표시 확인.
- 쿠키 전환 후 `PHPSESSID 쿠키` 마스킹 입력, 쿠키 보관 버튼과 펼칠 수 있는 취득 안내 확인. 데스크톱 및 390×844 모바일에서 안내가 읽히고 수평 overflow가 없었다. 사용자 쿠키를 입력하거나 전송하지 않았다.

브라우저 시나리오는 현재 수동 E2E이며 CI 자동화된 Playwright suite가 아니다. P3에서 확대/축소·포인터 스와이프를 추가 검증했으며 실제 터치 장치는 미검증이다. 실제 Pixiv 계정의 인증·페이지네이션·우고이라 ZIP 품질은 별도 PoC가 남아 있으며, 합성 자료 검증을 실계정 성공으로 해석하지 않는다.
