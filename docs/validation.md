1. **서버 이름으로 HTTP 접속할 때 작업 요청 실패.** 여러 수집/검사/변환/복구 버튼이 보안 컨텍스트에만 제공되는 `crypto.randomUUID()`를 직접 사용했다. 실제 `http://archive-server.example.net:18001` 격리 브라우저에서 secure context=false, randomUUID=undefined와 기존 방식의 실패를 재현했다. `getRandomValues` 기반 128비트 난수 요청 키를 중앙화하고 모든 8개 호출 위치를 바꿨다. 같은 브라우저에서 수정 방식 성공을 확인했으며 인증·CSRF·Origin 요구는 유지한다. API는 UUID 형식을 요구하지 않는 길이 제한 문자열이다. 브라우저 API 경계는 [randomUUID](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID)와 [getRandomValues](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues) 문서를 참고했다.

## 실제 Compose 및 worker 검증

일반 데이터와 분리한 `pixchive-smoke` 프로젝트에서 검사했다.

1. 이미지 build와 web/worker/Redis 시작.
2. 빈 볼륨 마이그레이션과 초기 키 생성.
3. 합성 작품 6개, 원본 8개 적재 및 관리자 세션 생성.
4. HTTP 202로 보관 검사 작업 등록, 실제 Redis 전달, worker에서 8개 파일 검증 완료.
5. worker 정지 상태에서 작업 생성, 테스트 Redis `FLUSHALL`, web/worker 재시작.
6. 기존 세션·작품 유지 및 queued DB 작업의 자동 회수·완료 확인.

기본 Docker bridge가 없는 호스트 특성으로 이미지 build에는 `--network=host`를 사용했다. 런타임은 Compose 전용 bridge다. 호스트 Docker 설정이나 다른 프로젝트는 수정하지 않았다. 실계정 동기화·실제 다운로드 중 강제 종료·장시간 부하·전체 백업 복원은 이 검증에 포함되지 않는다.

P2 이미지에 FFmpeg를 포함한 뒤 별도 합성 DB와 Redis DB 1로 ARQ worker를 실행했다. DB outbox의 변환 작업 전달 → ZIP/타이밍 검증 → 썸네일·MP4 생성 → 작업 `succeeded`와 bundle `ready`를 확인했다. 원본 2개가 남아 있고 파생 파일의 해시 검증이 통과했다. 실제 개발 서비스의 Redis DB 0과 데이터는 이 테스트에서 사용하지 않았다.

개발 환경 `localhost:8000`에도 스키마 v2와 최신 UI를 반영했다. 기존 관리자·표시 설정을 유지했고, `compose.dev.yml`의 Redis와 독립 worker 연결을 확인했다. 실계정 토큰 등록이나 Pixiv 요청은 실행하지 않았다.

## 쿠키 인증 전환 검증 (2026-09-28)

- PHPSESSID 암호화 보관, 값만 허용하는 입력 검증, 응답/검증 오류의 쿠키 비노출.
- legacy HTML 및 Next.js 홈페이지의 로그인 사용자 ID 검증, 익명/만료 세션 거부.
- 웹 API 공개/비공개 범위, 원본 페이지, 태그 원문/언어별 번역, 우고이라 `originalSrc`와 타이밍.
- 로그인/다른 호스트 redirect 거부, 홈페이지 언어 경로만 허용, 미디어 요청에 쿠키 없음.
- offset 재개 시 직전 항목과 총건수 확인, 종료 전 첫 항목/총건수 변경 검사.
- sparse/빈 북마크 태그 응답과 필드 누락 구분, 목록 형식 누락을 완료로 해석하지 않음.
- v2→v3 마이그레이션에서 이전 토큰 암호문 보존·쿠키 전송 차단·기존 커서 초기화.
- 실제 개발 서버와 worker를 v3로 재시작하고 기존 앱 로그인·표시 설정 유지 확인.

쿠키 전환 시점의 121개 테스트에는 이전 OAuth 테스트를 대체한 웹 API 계약 테스트가 포함된다. 실제 PHPSESSID 등록과 Pixiv 요청은 실행하지 않았다. 상세 조사 근거와 한계는 [Pixiv PoC](pixiv-poc.md)에 있다.

## 브라우저 E2E

FastAPI가 제공하는 실제 production build, 합성 원본, 임시 관리자 세션으로 확인했다. API 응답을 프런트엔드 mock으로 대체하지 않았다.

- 첫 설정 화면 표시 및 관리자 로그인.
- 1440×1000 desktop 라이브러리, 390×844 mobile 레이아웃과 수평 overflow 없음.
- 3페이지 작품의 다음 페이지 이동.
- 로컬 태그 추가 후 새로고침에도 유지.
- 한국어 로컬 태그 부분 검색과 검색 URL 반영.
- 전체 화면 뷰어, Escape 닫기, 버튼 focus 복귀.
- 목록 돌아가기 후 카드 focus 복귀.
- mobile 필터 열기/닫기와 focus 복귀.
- mobile 로그아웃 즉시 private 화면 제거 및 로그인 화면 전환.
- 우고이라 상세의 ZIP·타이밍 링크, 포스터와 MP4 컨트롤, 실제 반복 재생 확인. 합성 원본 400ms의 MP4는 401ms이며 재생 시 `currentTime`이 진행하고 오류가 없었다.
- 1280px desktop과 390×844 mobile에서 우고이라 상세 비율 유지 및 수평 overflow 없음.
- 설정의 수집 범위 선택 → 비공개 수집 등록 → 작업 목록 범위 표시 → 일시정지 → 취소 상태 반영. 네트워크 수집을 실행하지 않는 분리된 합성 환경에서 확인했다.
- 실제 개발 화면 새로고침 후 기존 로그인 유지, 새 수집 UI·우고이라 지원 설명·worker 연결 표시 확인.
- 쿠키 전환 후 `PHPSESSID 쿠키` 마스킹 입력, 쿠키 보관 버튼과 펼칠 수 있는 취득 안내 확인. 데스크톱 및 390×844 모바일에서 안내가 읽히고 수평 overflow가 없었다. 사용자 쿠키를 입력하거나 전송하지 않았다.

브라우저 시나리오는 현재 수동 E2E이며 CI 자동화된 Playwright suite가 아니다. P3에서 확대/축소·포인터 스와이프를 추가 검증했으며 실제 터치 장치는 미검증이다. 실제 Pixiv 계정의 인증·페이지네이션·우고이라 ZIP 품질은 별도 PoC가 남아 있으며, 합성 자료 검증을 실계정 성공으로 해석하지 않는다.
